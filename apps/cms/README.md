# Hibana CMS

Hibana の Web ライブラリを使う、単一管理者向けのブログ CMS です。画面・ルーティング・入力検証・記事 CRUD は `main.hb`、Node.js ホストとの接続・認証・ファイル保存は `runtime.mjs` にあります。記事はメモリだけでなく JSON ファイルに保存します。

## 起動

`apps/cms` で実行します。Rust / Node.js などの開発環境は Nix flake で用意できます。

```sh
nix develop -c cargo run -q -- build
# 例の文字列ではなく、自分専用の十分長いパスワードに置き換える
CMS_PASSWORD='replace-with-a-long-random-secret' nix develop -c node start.mjs
```

表示された URL（既定は `http://localhost:3000`）を開き、`/login` でログインします。`/admin` から記事の新規作成・編集・削除ができます。「公開」を選択して保存するとトップページと `/posts/{id}` に表示され、下書きは公開 URL からは読めません。本文は HTML / Markdown として実行せず、プレーンテキストとして表示します。

ソースを変更したらビルドコマンドを再実行し、サーバーを再起動してください。生成先は `apps/cms/dist/app.mjs` です。以前の `hibana js` サブコマンドは使いません。

設定は起動時の環境変数で渡します。

- `CMS_PASSWORD`: 必須、12〜1024文字。全管理者で共有する単一パスワード。
- `PORT`: 既定 `3000`。`0` なら空きポートを自動選択。
- `CMS_DATA_DIR`: 既定 `apps/cms/data`（起動ディレクトリからの相対パス）。運用では永続ボリュームの絶対パスを推奨。
- `CMS_SECURE_COOKIE=1`: HTTPS 運用時に必須。セッション Cookie に `Secure` を付与。ローカル HTTP では設定しないでください。

## データとバックアップ

記事はデータディレクトリの `posts.json` に保存します。保存は一時ファイルへの書き込み・fsync・rename・ディレクトリ fsync の順で行います。これは DB サーバーを使わない小規模運用向けです。同じデータディレクトリの二重起動は `.cms.lock` ディレクトリで拒否します。壊れた JSON や不正な記事データを発見した場合は、空のデータで上書きせず起動 / 操作を拒否します。

バックアップはサーバーを Ctrl+C / SIGTERM で停止してから `posts.json` を別の安全な場所へコピーしてください。復元も停止中に行い、ファイルの所有者・読み取り権限を維持します。記事、パスワード、バックアップは Git に入れないでください。

強制終了・電源断などで `.cms.lock` が残った場合は、同じデータを使うプロセスが本当に停止していることを確認してから、そのロックディレクトリだけを手動で削除して再起動します。動作中のロックを消すと保存の排他制御が壊れます。

## 認証と公開運用

パスワードは scrypt で照合し、推測しにくい乱数のセッションとセッション別 CSRF トークンを使います。Cookie は `HttpOnly; SameSite=Strict; Path=/`。セッションは8時間で期限切れ、再起動時に全失効します。ログイン失敗が5回続くと全体で60秒間の制限がかかります（IPごとの制限ではありません）。記事の変更とログアウトには認証と CSRF トークンが必要です。

インターネットに直接露出する完成済みのマネージドサービスではありません。公開する場合は HTTPS のリバースプロキシを前段に置き、`CMS_SECURE_COOKIE=1` と、アクセス制御・リクエストサイズ / タイムアウト制限・バックアップを設定してください。HTTP サーバーは localhost 専用に bind していないため、ローカル利用でもファイアウォールに注意してください。パスワードを変更するにはプロセスを停止し、新しい環境変数で再起動します。

## 現在の制約

- 単一プロセス・単一管理者・ローカルディスク保存。複数レプリカ、同時編集の競合解決、権限管理なし。
- 全記事を読み書きする方式。保存は最大10,000記事 / JSON 16 MiB、タイトル200文字・本文100,000文字のホスト上限あり。大規模な検索 / ページング用途には DB 層が必要。
- 画像アップロード、Markdown、リッチテキスト、予約公開、変更履歴、パスワードリセットなし。
- バックアップの自動化・監視・障害復旧は利用者が用意する必要があります。JSON の原子的な保存は別媒体へのバックアップの代わりにはなりません。

## テスト

```sh
nix develop -c node --test apps/cms/runtime.test.mjs
nix develop -c cargo test --test cms
```

後者は Hibana ソースから JS を生成し、本物の HTTP サーバーに対して認証、CSRF 拒否、記事作成・公開・削除、下書き非公開、HTML エスケープ、正常再起動後の永続化を検査します。実行に Node.js が必要です。本番デプロイやブラウザ操作を自動で検証するものではありません。
