# hibana の設計方針

hibana は、プログラム中で確かめた値の条件を型検査に使い、呼び出しに要るものを公開関数の宣言で伝え、同じ計算を Web とネイティブで使えるようにする。新しい機能は、利用者が書くコードで何を確かめ、何を呼び出し側に伝え、どこまで同じ意味で実行できるかから考える。

## 値を確かめた箇所を型検査に使う

細分化型は、条件を満たす値だけを許す型。引数の型や分岐の条件を使い、配列の添字が範囲内にあることや、割る数がゼロでないことを実行前に確かめる。標準入力から1桁の整数を読む `parse_digit` では、整数への変換と範囲の検査を実行時に行い、成功した枝の条件で `Digit` を証明する。入力が条件を満たさない場合は `Result`（成功か失敗を表す型）で呼び出し側へ返す。[言語仕様 7.1 節](spec.md#71-細分化型の証明)、[利用例](../examples/first.hb)

外部との境界でも、hibana 側で確認できた条件だけを型検査の前提にする。JavaScript や WebAssembly（WASM、実行環境に読み込ませるバイナリー形式）と接続するとき、外部から hibana に入る値は細分化する前の型で受け取る。必要な条件を `refine<T>`（実行時に条件を検査して `Result` を返す関数）や分岐で確かめる。[言語仕様 3.4 節](spec.md#34-javascript--typescript-のモジュール)、[WebAssembly との接続](wasm.md#javascript-との接続)

## 呼び出しに要るものを公開宣言で伝える

`with` は関数が呼び出し側に求める処理を表す。たとえば `with Logger` を持つ関数には、呼び出し側がログの処理を提供できる。公開関数は要求の節を明記し、呼び出す側が本体を読まずに要求を確認できるようにする。非公開関数では本体から要求を推論できる。現行の `with {}` は要求が空であることを表し、その関数から標準出力の `put` も呼べる。[言語仕様 3.5 節](spec.md#35-要求と提供with)、[利用例](../examples/first.hb)

## 共通の言語規則を実行方式間で揃える

hibana のコードと標準入出力で完結するプログラムでは、インタプリタ、JavaScript、WASM、ネイティブの間で実行結果の一致を目標とする。同じ入力に対して、標準出力の内容と順序、実行の成否、失敗報告の有無と回数、非同期処理の失敗後に続く処理を揃える。たとえば、非同期処理を待つ書き方には全方式で `.await` を使う。外部関数との接続や成果物の書き出しのように実行環境に依存する機能は、使える方式と受け渡しの規則を示す。[用語集](../GLOSSARY.md)、[待ち方と累乗の設計判断](adr/0001-align-language-semantics-across-backends.md)、[言語仕様 11.1 節](spec.md#111-コマンドとコード生成-api)

## 言語の仕組みを使って用途を広げる

既存の言語規則で表現できる機能は、まずライブラリやマクロ（ソースを展開してコードを作る仕組み）で試す。たとえば `unless` は `if` に展開され、展開後に分岐の条件が型検査で使われる。Web 用の接続コードと TypeScript の型宣言は、コンパイラが出す受け渡し規約をもとに `std::wasm_web` が生成する。言語本体に機能を加える場合は、既存の仕組みで表現できない規則と、その規則を共有する実行方式を示す。[利用例](../examples/first.hb)、[言語仕様 8 章](spec.md#8-マクロ)、[WebAssembly の生成例](wasm.md#hibana-のビルドスクリプトで生成する)

## 変更を判断するとき

1. 利用者が書くコードを先に示す。既存の `examples/` は書き方と動作の基準とし、足りないケースはテスト用のプログラムで確かめる。
2. そのコードが受理される条件と、失敗を返す箇所を決める。型が保証する条件と公開関数の要求は、外部との境界や出力先を加える場合も保つ。
3. 対応範囲と実装する場所を決める。共通の機能は、対象の実行方式で成功時と失敗時の差をテストする。特定の環境だけで使う機能は、その境界で検査する値と失敗の返し方を確かめる。

出力先の都合で選択肢が分かれたときは、共通コードの型の保証と実行結果の一致を優先する。環境ごとの違いは接続部分で扱う。共通の規則を変える理由がある場合は、影響する利用例と移行後の書き方を示す。

たとえば、Web 向けの公開関数に `Digit` を渡せるようにする提案では、現在は `int` で受け取って hibana 側で範囲を調べ、条件に合わない入力を `Result` で返せる。境界に `Digit` を直接書けるようにするには、誰が範囲を検査し、条件に合わない入力をどの型や例外で返すかを先に決める。この判断があれば、同じ入力を処理する既存の書き方とも比較できる。[WebAssembly との接続](wasm.md#javascript-との接続)
