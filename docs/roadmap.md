# 開発ロードマップ

## 同期の `main` が失敗した後も開始済みの処理を進める

同期の `main` が `spawn`（非同期処理を開始する関数）で処理を始め、直後に `panic()` を呼ぶ例を実行しました。開始した処理は `.await`（非同期処理の完了を待つ式）の後に `42` を表示します。インタプリタと JavaScript は `42` を出力してから `main` の失敗を報告します。WebAssembly とネイティブは `42` を出力する前に停止します。非同期の `main` で `all`（複数の非同期処理をまとめて待つ関数）の実行中に失敗した例では、他の処理が続くことを4方式で確認しました。[非同期の仕様](spec.md#非同期) [比較テスト](../tests/backend_parity.rs)

WebAssembly とネイティブで、同期の `main` の失敗を保持し、開始済みの処理を進めてから報告します。成功した処理に `then` で登録した関数も実行し、その関数も失敗した場合は `main` の失敗を優先します。4方式で出力、報告の内容と回数、失敗終了が揃い、生成した JavaScript 接続を使った WebAssembly の呼び出しも処理が終わってから例外を投げれば完了です。[非同期のテスト](../tests/async.rs) [WebAssembly のテスト](../tests/web.rs)

## 外部関数から受け取る真偽値と文字列を検査する

`extern`（外部関数の宣言）で `bool` を返すと宣言した関数から JavaScript の数値 `1` を返すと、JavaScript 出力は `1` を表示し、WebAssembly の接続コードは「真偽値が必要」で停止します。`String` を返すと宣言した関数から数値 `7` を返す場合も、JavaScript 出力は処理を続け、WebAssembly は「文字列が必要」で停止します。[JavaScript / TypeScript との連携](spec.md#34-javascript--typescript-のモジュール) [WebAssembly の接続](wasm.md#javascript-との接続)

JavaScript 出力でも、外部関数の戻り値と、外部関数から hibana の関数を呼ぶときの引数を宣言どおりに検査します。真偽値・文字列と、それらを含む配列の要素や構造体のフィールドを対象にします。JavaScript と WebAssembly で、同じ不正な戻り値を拒否し、正常な値では処理が続くことを確かめます。JavaScript の非同期の戻り値と、外部関数に渡した hibana の関数の引数もテストし、境界の規則を仕様に記載します。[JavaScript の変換](../src/backend/js.rs) [WebAssembly のテスト](../tests/web.rs)

## 関数型と細分化型を含む要求を推論する

非公開関数では、本体から `with` の要求（呼び出し側が提供する処理）を推論する規則があります。要求の型引数が `(int) -> int` のような関数型や `Digit` のような細分化型（条件を満たす値だけを許す型）の場合、現在はその要求を推論できず、型検査で `with` を書くよう求められます。どちらも `with` を明記すると4方式で実行できます。[要求の仕様](spec.md#35-要求と提供with) [要求の推論](../src/check/effects.rs)

推論した要求に関数型の引数型・戻り値型・要求と、細分化型の条件を保持します。`with` を省いた非公開関数を別の非公開関数から呼び、呼び出し元にも要求が伝わることを確かめます。提供があるときは明示した場合と同じ出力になり、提供がないときや、異なる要求を明示したときは型検査でエラーになれば完了です。[要求のテスト例](../tests/programs/effects/with.hb) [モジュールのテスト](../tests/modules.rs)

## 同じ型に適用できるトレイト実装を検出する

トレイト（型に対する操作の宣言）の同じ実装を2つ用意すると、現在は一方が選ばれます。同じファイルと別モジュールの両方で確認しました。`Vec<T>` 全体の実装と `Vec<int>` の実装を用意した例でも、`Vec<int>` に一方が選ばれます。[トレイトの仕様](spec.md#37-トレイト) [実装の探索](../src/check/traits.rs)

同じトレイト名・型引数・対象型に適用できる実装が複数ある場合は、型エラーにして両方の宣言位置を示します。具体型で一致する組と、制約のない型引数に具体型を当てはめると一致する組を対象にします。同一ファイルと別モジュールの衝突を検出し、`Vec<int>` と `Vec<String>` のように対象型が異なる実装は両方使えることを確かめます。規則を仕様に記載し、全テストが通れば完了です。[モジュールのテスト](../tests/modules.rs)

## 完了：`number` の文字列表記を揃える

`number`（64 ビット浮動小数点数）の組み込みの文字列化を4方式で揃えました。実施前は `put(1000000000000000.25)` の出力がインタプリタで末尾 `3`、他の3方式で末尾 `2` でした。実施後は元の値に丸め戻せる最少桁の十進表記を使い、等距離なら末尾が偶数の候補を選びます。指数表記を使わず、負のゼロの符号を保ちます。[組み込み関数](spec.md#9-組み込み関数)

正負の等距離の値、負のゼロ、整数部が23桁の値で、`put`、`to_string()`、`stringify(JNum(n))`（JSON の数値を文字列にする処理）の出力が4方式で一致し、JSON を読み直すと元の値と負のゼロの符号に戻ることを確認します。[比較テスト](../tests/backend_parity.rs) [JSON の仕様](spec.md#10-ライブラリ)

### 2. 待ち方と累乗を揃える

- `Task.wait()` を廃止します。`Async`（実行を始める前の非同期処理）を待って値を使う場合は `.await`、開始済みのタスクの成功後に関数を呼ぶ場合は `then` を使います。`Task.wait()` は4方式が共有する型検査で拒否します。
- `**` で受け付ける指数を整数値に揃えます。`number` の指数に小数部分があれば、4方式とも実行時エラーです。平方根には `std::math::sqrt` を使います。

小数の指数を使う例と整数値の指数を使う例で4方式の成否と結果が揃い、`Task.wait()` を使う例が4方式で拒否され、移行例が動けば完了です。規則と移行方法を言語仕様に反映します。[設計判断](adr/0001-align-language-semantics-across-backends.md)

### 3. 非同期の失敗処理を揃える

- `spawn` したタスクの算術エラーは、そのタスクの失敗として1回報告します。他のタスクは続きます。
- `then` に渡した関数が失敗すると、残りの処理を動かしてからプログラム全体を失敗として終えます。

ゼロ除算と範囲外の整数演算について、失敗したタスクに登録した `then` が呼ばれず、別のタスクが出力することを4方式で確かめます。`then` に渡した関数の失敗では、後続の関数が出力してから全体が失敗することを確かめます。既存の `panic()` のテストも通ることを完了条件とします。
