## 次の到達点：標準入力の失敗報告を揃える

`input()` で不正な UTF-8（文字の符号化方式）の1行を読むと、4方式とも実行時エラーになります。インタプリタは標準入力の読み取り失敗として報告し、JavaScript は復号器のメッセージを出します。WebAssembly とネイティブは、標準入力の文字コードが UTF-8 でないと報告します。

1. 正常な1行の後に不正なバイトを渡すテストと、標準入力の読み取り自体を失敗させるテストを加えます。不正な入力より前の出力が残り、失敗した `input()` の後の文が実行されないことを4方式で確かめます。[入力テスト](../tests/input.rs)
2. インタプリタと JavaScript でバイトの読み取りと文字列への変換を分けます。WebAssembly を Node.js（JavaScript の実行環境）で動かす場合も、読み取りの失敗を既存の失敗処理に渡します。読み取りに失敗したときは「標準入力を読めません」、不正な UTF-8 のときは「標準入力の文字コードが UTF-8 でない」を使い、標準エラーに1回報告します。[共通の入力処理](../src/backend/runtime.hb) [Node.js 接続](../src/pipeline.rs)
3. 改行、CRLF（復帰と改行からなる行末）、空行、改行のない最終行、入力終了、読み取り区画をまたぐ行の結果を4方式で確認します。報告と返り値の規則を仕様に記載し、全テストが通れば完了です。[組み込み関数](spec.md#9-組み込み関数) [入門例のテスト](../tests/first.rs)

## その次の到達点：無名関数が写し取った変数への代入を揃える

無名関数（名前を付けずに作る関数）が、外側の `let mut` 変数へ代入する場合に、次の呼び出しから見える値が実行方式によって異なります。次の例で、インタプリタ・WebAssembly・ネイティブは `1`, `1`, `10` を、JavaScript は `1`, `2`, `10` を出力しました。

```hibana
fn main() {
    let mut n = 0
    let next = fn() -> int {
        n = n + 1
        n
    }
    n = 10
    put(next())
    put(next())
    put(n)
}
```

無名関数は呼び出しのたびに作成時に写し取った値から始め、その呼び出し中の代入はその呼び出しで使います。別の呼び出しと状態を共有する場合は `Ref`（書き換えられる参照）を使います。JavaScript 出力をこの規則に揃え、同じ無名関数を2回呼ぶ場合と、写し取った `Ref` の書き換えが次の呼び出しから読める場合を4方式で比較します。規則を仕様に記載し、全テストが通れば完了です。[式の仕様](spec.md#4-式) [比較テスト](../tests/backend_parity.rs)

### 2. 待ち方と累乗を揃える

- `Task.wait()` を廃止します。`Async`（実行を始める前の非同期処理）を待って値を使う場合は `.await`、開始済みのタスクの成功後に関数を呼ぶ場合は `then` を使います。`Task.wait()` は4方式が共有する型検査で拒否します。
- `**` で受け付ける指数を整数値に揃えます。`number` の指数に小数部分があれば、4方式とも実行時エラーです。平方根には `std::math::sqrt` を使います。

小数の指数を使う例と整数値の指数を使う例で4方式の成否と結果が揃い、`Task.wait()` を使う例が4方式で拒否され、移行例が動けば完了です。規則と移行方法を言語仕様に反映します。[設計判断](adr/0001-align-language-semantics-across-backends.md)

### 3. 非同期の失敗処理を揃える

- `spawn` したタスクの算術エラーは、そのタスクの失敗として1回報告します。他のタスクは続きます。
- `then` に渡した関数が失敗すると、残りの処理を動かしてからプログラム全体を失敗として終えます。

ゼロ除算と範囲外の整数演算について、失敗したタスクに登録した `then` が呼ばれず、別のタスクが出力することを4方式で確かめます。`then` に渡した関数の失敗では、後続の関数が出力してから全体が失敗することを確かめます。既存の `panic()` のテストも通ることを完了条件とします。
