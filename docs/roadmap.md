# 開発ロードマップ

次の到達点は、hibana のコードと標準入出力で完結するプログラムを、インタプリタ、JavaScript、WebAssembly、ネイティブの4方式で同じ仕様に従って実行できることです。4方式で受け付ける言語機能を揃え、同じ入力に対して実行結果の一致を確かめます。[用語集](../GLOSSARY.md)

## 現状

`a47e69a` では、`nix develop -c cargo test -q` の135件が通りました。入門例は3種の標準入力を使って4方式の出力を比較しています。整数の範囲外のエラーや非同期の `panic()` も個別に比較しています。[入門例のテスト](../tests/first.rs) [数値のテスト](../tests/numeric.rs) [非同期のテスト](../tests/async.rs)

| ケース | インタプリタと JavaScript | WebAssembly とネイティブ |
| --- | --- | --- |
| `Task.wait()` でタスクの完了を待つ | インタプリタは実行し、JavaScript は生成時に拒否する | WebAssembly は生成時に拒否し、ネイティブは実行する |
| `2.0 ** 0.5` を表示する | `1.4142135623730951` を出力する | 実行時エラーで停止する |
| `spawn`（非同期処理を開始する関数）で始めたタスクが待機後にゼロ除算する | 失敗を報告し、別のタスクを動かして成功で終わる | 全体が失敗し、別のタスクが動く前に停止する |
| `then`（成功後に呼ぶ関数の登録）に渡した関数が `panic()` で失敗する | 後続の関数を動かしてから失敗する | 後続の関数が動く前に失敗する |
| `put` で `Task`（開始済みの非同期処理を表す値）を表示する | インタプリタは `<task>` を出力し、JavaScript は実行時エラーになる | `(0, (), <ref>)` を出力する |
| 制御文字（改行や後退など、表示を制御する文字）を含む配列を `put` で表示する | インタプリタと JavaScript で表記が異なる | インタプリタと JavaScript のいずれとも異なる表記を使う |

WebAssembly の公開関数の型や外部関数を通じた連携など、実行環境との接続には方式ごとの仕様があります。[言語仕様](spec.md#11-実行方式) [WebAssembly](wasm.md#javascript-との接続)

## 1. 4方式の差をテストで再現する

既存の4方式を比較するテストの実行方法を使い、表の各ケースを再現します。標準出力の内容と順序、標準エラーへの失敗報告の有無と回数、成否を記録します。非同期のケースでは、失敗後に動く処理を出力で確かめます。

各差について、現在の結果と合意した結果をテストから確認できれば完了です。動作を変更する作業と合わせて、テストの期待値を4方式で共通にします。

## 2. 待ち方と累乗を揃える

- `Task.wait()` を廃止します。`Async`（実行を始める前の非同期処理）を待って値を使う場合は `.await`、開始済みのタスクの成功後に関数を呼ぶ場合は `then` を使います。`Task.wait()` は4方式が共有する型検査で拒否します。
- `**` で受け付ける指数を整数値に揃えます。`number` の指数に小数部分があれば、4方式とも実行時エラーです。平方根には `std::math::sqrt` を使います。

小数の指数を使う例と整数値の指数を使う例で4方式の成否と結果が揃い、`Task.wait()` を使う例が4方式で拒否され、移行例が動けば完了です。規則と移行方法を言語仕様に反映します。[設計判断](adr/0001-align-language-semantics-across-backends.md)

## 3. 非同期の失敗処理を揃える

- `spawn` したタスクの算術エラーは、そのタスクの失敗として1回報告します。他のタスクは続きます。
- `then` に渡した関数が失敗すると、残りの処理を動かしてからプログラム全体を失敗として終えます。

ゼロ除算と範囲外の整数演算について、失敗したタスクに登録した `then` が呼ばれず、別のタスクが出力することを4方式で確かめます。`then` に渡した関数の失敗では、後続の関数が出力してから全体が失敗することを確かめます。既存の `panic()` のテストも通ることを完了条件とします。

## 4. 値の表示を揃える

`put` に渡した `Task` の表記と、配列などの中にある文字列の制御文字を表示する規則を言語仕様に定め、4方式の出力を揃えます。`Task` と、制御文字を含む文字列を入れ子にした配列の出力が、4方式で規則どおりになれば完了です。[組み込み関数](spec.md#9-組み込み関数)

この到達点は、現状の表に挙げた差を解消し、入門例と4方式の比較テストが通った時点で完了です。以降は、共通の言語機能を追加・変更する作業で、仕様の更新と4方式の比較を行います。
