# hibana 言語仕様

hibana は、細分化型と、構文を拡張できるマクロを根幹に置く言語です。実装は Rust で、`nix develop` の中で `cargo run -- <ファイル.hb>` で実行します。証明に使う Z3 は、z3 クレートでライブラリ（libz3）を直接呼びます。`nix develop` でビルドした実行ファイルは libz3 の場所を rpath に持つので、外でもそのまま動きます。`cargo build --features static` は Z3 をソースからビルドして静的にリンクします（配布用。時間がかかり、cmake が要ります）。

この文書は実装（`src/`）の現状を書いたものです。例は `tests/programs/` にあります。利用者が書く正本は `examples/` です。

## 1. 字句

- 識別子は Unicode の文字か `_` で始まり、文字・数字・`_` が続きます。
- 整数（`42`、`0xFF`）、浮動小数（`3.14`）、文字列（`'a\n'`、`"a\n"`）を書けます。文字列は一重引用符か二重引用符で囲みます。エスケープは `\n \t \r \0 \\ \' \" \` \{ \}` です。JSX は組み込みの構文ではありません。マクロの構文（8.1 節）で `<tag>` の形を定義でき、その本文は `Text` 規則で読みます。式として使えない文字は構文解析で拒否します。
- `` `Hello {name}!` `` は埋め込み付きの文字列です。`{ }` の中に式を1つ書き、その値を文字列にしてつなぎます（`'Hello ' + name.to_string() + '!'` と同じ）。`{ }` の中には `'...'` や入れ子の `` `...` `` も書けます。
- `型の名前::名前`（`Response::text`）は1つの名前です（3.9 節）。
- コメントは `// 行末まで` と `/* ... */` です。
- キーワード: `fn pub let mut if else while for in break continue return exit match type struct enum trait impl syntax macro quote use module extern await true false`
- 各トークンは、直前に空白があるか（`gap_before`）と改行があるか（`nl_before`）を持ちます。前者はマクロのパターンの `~`（空白なしで続く）に、後者は文の区切りに使います。

## 2. 文の区切り

文は改行で終わります。`;` を書いても構いません。行頭の二項演算子・`(`・`.`・`[` は前の行に続かず、新しい文の始まりになります。式を複数行に分ける時は、演算子を行末に置きます。

## 3. 宣言

ファイルの最上位には `use`・`fn`・`type`・`struct`・`enum`・`trait`・`impl`・`extern`・`syntax`・`macro` を並べます。宣言の順序は自由で、後で宣言した型や関数・マクロも使えます。`main` という引数の無い関数が入口です。

### 3.1 関数

```
fn add(x: int, y: int) -> int { x + y }
fn map<A, B>(f: (A) -> B, l: List<A>) -> List<B> { ... }
```

- 戻り値の型を省くと `unit`（値の無いこと）です。この場合、本体の最後の式の値は捨てます。
- 本体の最後の式が戻り値です。途中で返す時は `return` を使います。
- `<A, B>` はジェネリック引数です（`<A>` は `<A: Type>` の省略形）。呼ぶ側では省くことができ、引数の型と期待する型から推論します。明示する時は `map<int, int>(f, l)` と書きます。
- 関数は型を値として受け取ったり返したりできません。型引数は `fn id<A>(x: A) -> A` のように宣言します。
- モジュール外から呼ぶ関数は `pub fn` で宣言し、`with` の節を明示します。要求が無い場合は `pub fn id<A>(x: A) -> A with {} { x }` と書きます。

### 3.2 型

型の宣言は3種類です。`struct` と `enum` は実行時に値として残る形を、`type` は型検査のためだけの型（型の別名）を宣言します。

```
// 構造体。値は Point { x: 1, y: 2 } で作り、p.x で取り出す
struct Point { x: int, y: int }

// フィールドに名前の無い構造体。int とは別の型になる。値は UserId(42) で作り、id.0 で取り出す
struct UserId(int)

// 直和型。構築子は , か改行で区切る
enum Nat { Zero, Succ(n: Nat) }
enum Option<T> { None, Some(x: T) }
enum Shape { Circle(Point, int), Empty }   // フィールドの名前は省ける（0, 1, ... になる）

// 別名。型引数（`<A>`）を取れる。実行時には消える
type Pos = int[x -> x > 0]
```

- 型の引数は `<>` で宣言し、`<>` で渡します（`Option<int>`）。値の引数は `()` で渡します（`Some(3)`）。型の名前に `()` で引数を渡すとエラーです（`struct Name(型)` の構造体の値を作る時を除く）。
- 構築子の型引数は推論します。`let o: Option<int> = None` のように期待する型から、`Some(3)` のように引数の型から求めます。
- 構築子は `Shape::Circle(p, 2)` のように型の名前を付けても書けます。`match` の腕でも同じです（`Shape::Circle(c, r) -> ...`）。
- 構造体の値のフィールドの順序は自由です。構造体は、構築子を1つ持つ型として扱います。`struct Name(型, ...)` のフィールドの名前は `0`、`1`、... で、`Name(1, 2)` と表示します。
- `type Name = { ... }` と `type Name = A | B` はエラーで、`struct` と `enum` を使うよう伝えます。
- 名前の決まり: 組み込みの型は `int number bool String syn unit`、利用者が宣言する型は大文字で始めます。

`number` は有限な IEEE 754 の64ビット浮動小数点数（`f64`）です。旧型名 `num` は使えません。`int` は `number` の部分型で、整数かつ `-9007199254740991` から `9007199254740991`（±(2^53 − 1)）の範囲です。この範囲の整数は `f64` でも丸めずに表せます。範囲外の整数リテラルは型エラーです。`2.0` のように小数点を付けた値は `number` になります。

`int` は `number` が必要な位置にそのまま渡せます。`Vec<T>` は共変（要素の部分型関係を配列にも適用する）なので `Vec<int>` を `Vec<number>` へ渡せます。書き換え可能な `Ref<T>` を含むデータ型の引数は不変（引数の型が一致するときだけ代入できる）です。`if`・`match`・配列リテラルでは共通上位型を求め、`int` と `number` は `number` へ結合します。例えば `[1, 2.5]` は `Vec<number>` です。

`+ - * / % **` と単項 `-` は、オペランドの静的な型で演算を選びます。両方が `int` またはその細分化型なら53ビット安全整数演算です。範囲を超えた結果は実行時エラーになり、`std::try_overflow` で処理を囲むと失敗を `Result` で受け取れます（10 章）。整数除算は0へ切り捨てます。片方が `number` なら `f64` 演算で、除算の小数部分を保ちます。関数での整数演算にオーバーフローの事前証明は要りません。`/` と `%` の割る数が 0 でないことはコンパイル時に証明します（7.1 節）。有限でない浮動小数点数の結果は実行時エラーです。`floor` は切り下げ、`refine<int>(x)` は整数性と安全整数の範囲を検査し、整数なら `Ok`、小数や範囲外なら `Err` を返します。

`number` の証明は整数用の規則と Z3 の整数式へ渡しません。定数評価と既知の条件との一致に加え、非負の和・積・平方根、非負の数を正の数で割った商の非負性を扱います。商や積の正値性はアンダーフロー（絶対値が小さい結果が0に丸められること）があるため推論しません。閉区間の端点を `f64` の丸めに従って加算・減算・乗算・符号反転へ伝播し、その区間から比較を証明します。端点の演算が非有限ならその伝播は行いません。

`x < x + c` と `x - c < x`（定数 `c > 0`）は、`x` の有限区間 `[lo, hi]` が既知で、結果の両端も有限、かつ `c >= 2 * (next_up(m) - m)`（`m = max(abs(lo), abs(hi))`）のとき証明します。`next_up` は次に大きい浮動小数点数で、差は ULP（隣接する浮動小数点数の間隔）の余裕を表します。上界のない `x: number` で `x + 1.0 > x` は証明しません。

累乗の指数は整数値に限ります。`number` の指数に小数部分があれば実行時エラーです。4方式で乗算の順序をそろえ、丸めの結果を一致させます。平方根には `std::math::sqrt` を使います。

### 3.3 モジュール

```
use std              // 組み込みのライブラリ（lib/ 以下。実行ファイルに埋め込まれている）。std::map のように修飾して使う
use std -> *         // すべての名前を修飾なしで使う
use std -> {map, Option}  // 挙げた名前だけ修飾なしで使う
use std::math
    -> { floor }     // 名前の取り込みは改行して続けて書ける
    -> { sqrt }
use util             // このファイルと同じディレクトリの util.hb。util::foo() と呼ぶ
use foo::bar         // foo/bar.hb。bar::foo() と呼ぶ
use foo::bar -> {foo} // foo() と呼ぶ
use foo::bar -> *     // すべての名前を修飾なしで使う
```

- `use` したモジュールの関数・型・構築子は `モジュール名::名前`（`std::map(xs, f)`、`std::Some(1)`、`std::Option<int>`）で参照します。`モジュール名.名前` の形はメソッドかフィールドとして読むので、モジュールの参照には使えません（エラーで `::` の形を案内します）。モジュール名で修飾できるのは、`->` を付けない `use` を書いたファイルの中だけです。`use std -> *` や `use std -> {map, Option}` だけでは `std::map` と書けず、`map` と書きます。利用者のファイルの同じ名前とは衝突しません。
- 型の名前を取り込むと、その型に属する関数（`Response::text` など）も修飾なしで使えます。
- モジュールの中では、そのモジュール自身の名前を修飾なしで参照できます。
- 関数・型別名・構造体・列挙型・トレイトは、宣言に `pub` を付けたものだけをモジュール外から参照できます。`pub struct Point { x: int }`、`pub enum Choice { Yes, No }`、`pub type Count = int` のように書きます。構築子とフィールドの公開範囲は型の公開範囲に従います。トレイトのメソッドと要求の操作もトレイトの公開範囲に従い、公開トレイトのメソッドには `with` を明示します。
- 非公開の名前は、モジュール名による修飾・`-> *`・`-> {名前}` のいずれでも参照できません。型に属する関数は、その関数自身に `pub` が必要です。`extern` の公開関数はブロック内で `pub fn` と書きます。`impl` には `pub` を付けません。
- 名前は、局所変数、自分のモジュール、`use` で修飾なしに取り込んだ名前の順に探します。
- `Result`、`Ok`、`Err`、`parse_int` は `use` なしで使えます。自分のモジュールと明示した `use` の名前を先に探し、見つからなければ `std` の名前を使います。必要になった時に標準ライブラリを読み込みます。
- `syntax` と `macro` の宣言名はモジュールごとに管理します。`use` による規則の参照とマクロの取り込みは 8.1 節で説明します。マクロの展開結果がライブラリの関数や型を使う場合、衛生性（展開した名前が呼び出し側の名前と衝突しない性質）により定義側の名前を参照します。
- 同じモジュールは1回だけ読みます。
- 名前による指定は組み込みライブラリを先に探し、なければ `::` をディレクトリの区切りに置き換えて `.hb` を付けます。経路は `use` を書いたファイルのディレクトリから解決します。参照に使うモジュール名は最後の名前（`foo::bar` なら `bar`）です。最後の名前が同じでも、異なるファイルなら重複エラーになります。
- `use` には `std::math` や `util` のようにモジュール名を書きます。外部関数は `extern` で宣言します（3.4 節）。

### 3.4 JavaScript / TypeScript との連携

JavaScript に出力して外部関数を呼ぶときは、hibana の引数型と戻り値型を `extern` で宣言します。インタプリタで外部関数を呼ぶと実行時エラーになります。

```
extern './js/util.ts' {
    fn add(x: number, y: number) -> number
}

fn main() {
    put(add(2, 3))
}
```

`extern` の文字列は生成される JavaScript の `import` に渡ります。相対経路は生成した JavaScript の位置を基準に解決します。npm パッケージ名や `node:path` のような Node.js の組み込み名も指定できます。複数のファイルから使う宣言には `pub fn` を書き、その宣言を含む hibana のモジュールを名前で読み込みます。

| hibana の型 | 境界での変換 |
|---|---|
| `int` | JavaScript の安全整数 |
| `number` | 有限な JavaScript の数値 |
| `String`・`bool` | JavaScript の文字列と真偽値 |
| `unit` | 戻り値を捨てる |
| `Vec<T>` | JavaScript の配列を要素ごとに変換 |
| 構造体 | 同じフィールド名の JavaScript オブジェクト |
| `(A) -> B` | 引数と戻り値を変換するよう関数を包む |
| 関数宣言の `-> T with Async` | 処理の完了を表す JavaScript の `Promise<T>` を `.await` で待つ（3.5 節） |
| `(A) -> B with Async` | JavaScript 側では Promise を返す関数 |
| `js` | JavaScript の値をそのまま渡す |

- JavaScript から受け取る `bool` と `String` は、宣言した型と異なる場合に実行時エラーになります。配列の要素と構造体のフィールドも検査します。この規則は外部関数の戻り値、Promise が返す値、外部関数から呼び出す hibana の関数への引数に適用します。
- 外部から hibana に入る値の型に細分化型を書くと、コンパイルエラーになります。外部関数の戻り値、配列の要素、構造体のフィールド、関数を渡した先から戻ってくる値にも適用します。コールバック（外部関数から呼び出す hibana の関数）の引数も対象です。細分化する前の型で受け取り、`refine<T>` で条件を検査できます。

### 3.5 要求と提供（with）

`with` は、呼び出し側の文脈から受け取るものを表します。関数は受け取るものを `with` の節で要求し、呼ぶ側は `with` ブロックで提供します。失敗・依存の注入・ログなどの文脈はトレイト（3.7 節）で宣言し、非同期は組み込みの `Async` で表します。要求のメソッドを呼ぶと、外側の `with` が渡した関数がそれを処理し、値を返せば呼んだ所から続きます。提供は、型検査が書き足す隠れた引数（文脈）で呼び出し先へ渡します（実装の節）。例は `tests/programs/effects/with.hb`・`effects.hb`・`async.hb` です。

```
trait Need<T> { fn need(self) -> T }
// Fail<E> は std にある: trait Fail<E> { fn fail(self, e: E) -> never }

fn find(id: String) -> User with Fail<NotFound>, Need<Db> {
    let db = need()
    if id == '0' { fail(NotFound { id: id }) } else { User { name: db.prefix + id } }
}

fn main() {
    let name = with Need(fn() { Db { prefix: 'u' } }),      // 値を返すと、呼んだ所が続く
                    Fail(fn(e) { exit 'not found: ' + e.id }) {   // exit で with を抜け、with の値にする
        find('42').name
    }
}
```

要求する側:

- 関数の宣言の戻り値の型の後ろに `with 要求, ...` と書きます（要求の節）。要求はトレイト（`Fail<NotFound>`・`Log`）、`Async`、要求の変数（`R`）です。同じ要求は一度だけ書けます。`!` を書くとエラーで、`with` で書くよう伝えます。
- 名前の無い要求（`with Log`）は、トレイトのメソッドを `self` を除いた引数で、修飾なしの関数として呼べます（`log(m)`・`fail(e)`）。
- 名前を付けた要求（`with Logger(logger)`）は、`logger.log(m)` と呼びます。名前の有無で意味は変わらず、違うのは呼び方だけです。名前は `名前.メソッド(...)` の形でだけ使え、値として渡したり保存したりはできません。別の関数で同じ提供を使うには、その関数にも `with Logger` を書きます（提供は隠れた引数で届きます）。
- 修飾なしの `m(...)` は、`m` が変数・関数でなければ、今使える名前の無い要求（関数の節と、囲む `with` ブロックが提供するもの）のうち `m` を持つトレイトのメソッドを呼びます。2 つ以上あれば型エラーで、名前を付けて呼ぶよう伝えます。使える要求に無ければ、`m` を持つトレイトが 1 つの時だけそのメソッドを呼びます（要求の推論と、書き忘れのエラーのため）。
- 要求の節を書いた関数で、書いていない要求を使うと型エラーです。要求を持つ関数を呼ぶ関数も、その要求を書くか `with` ブロックで提供する必要があります。
- 要求の節を省いた非公開関数は、本体から要求を推論します。再帰と相互再帰の関数は、要求が変わらなくなるまで推論を繰り返します。繰り返しの上限（推論する関数の数 + 4 回）までに収束しなければエラーです。推論した要求は書いた要求と同じに扱うので、`Async` を推論した関数の呼び出しは `Async<T>` の値になります。期待する型の無い無名関数（`let f = fn(x: int) { ... }`）も、本体から要求を推論します。
- 推論した要求の型引数に関数型や細分化型が含まれる場合は、関数型の引数・戻り値・要求と、細分化型の条件が呼び出し元にも伝わります。
- `pub fn` では要求の節を省けません。要求が無い場合は `with {}` と書きます。非公開関数でも `with {}` を書くと要求を推論しません。公開関数の本体が宣言に無い要求を使った場合は、その本体の呼び出し位置でエラーにし、公開関数の要求を変更しません。
- `main` が要求できるのは `Async` だけです。要求の節を省いた `main` は、本体で `Async` を使った時だけ `Async` を持ちます。
- 関数型にも要求を書けます（`(String) -> unit with Log`）。期待する型が要求を持つ関数型なら、無名関数の中でその要求を使えます。要求の少ない関数は、多い関数型の値として使えます（要求の無い関数を `with Log` の引数に渡せる）。要求を持つ関数も値として代入・受け渡しができ、その値を呼ぶ所で要求を使います。
- 引数の並びの中で、要求を持つ関数型の後に名前の無い引数が続く時は、関数型を括弧で囲みます（`(int, ((int) -> int with Log), String) -> int`）。
- 要求の多相: `<R: Effect>` は要求の並びを表す型引数です（種類の名前は `Effect`）。`fn map<A, B, R: Effect>(xs: Vec<A>, f: (A) -> B with R) -> Vec<B> with R` を呼ぶと、`R` は渡した関数の要求になり（要求の無い関数なら空）、`map` もその要求を持ちます。`R` にはトレイトの要求と `Async` の両方が入ります。std の `map` `filter` `fold` `some` `every` `find` がこの形です（例は `tests/programs/effects/poly.hb`）。
  - 渡す無名関数の引数の型は、前の引数から決まった関数型の引数の型から推論します（`map([1, 2], fn(x) { x * 2 })`）。戻り値の型と要求は本体から求め、`R` は本体で使った要求のうち、関数型に書いた要求の残りになります。関数型に `Fail<E>` があれば、本体の `Fail<String>` から `E` を決めます（`try` の `f`）。
  - JavaScript では、要求の多相な関数ごとに、要求の変数を通した呼び出しを待つ async 版（`f_map$a`）も出力し、`R` に `Async` が入る呼び出しはそちらを呼んで待ちます（async かどうかだけの単相化）。

提供する側:

- `with T(値), U(値) { 本体 }` は、本体で使った `T`・`U` の要求を値で提供します。値はブロックに入る時に一度評価します。入れ子では内側を使い、抜けると外側に戻ります。ブロックの値は本体の値です。
- 値は `T` を `impl` した型の値か、無名関数です。無名関数は `T` のメソッドが 1 つの時だけ使え、引数はそのメソッドの `self` を除いた引数です。値の型に `T` の実装が無ければ型エラーです。
- 返す＝再開: 提供した関数が値を返すと、要求のメソッドを呼んだ所でその値が戻り値になり、続きが動きます。戻り値が `never` のメソッド（`fail`）を提供する関数は値を返せず、`exit` で抜けます。
- `exit 式` は、その無名関数を書いた `with` ブロックを抜け、ブロックの値を `式` にします。`exit` の型は `never` で、`式` の型はブロックの型と一致する必要があります。`exit` は `with` の見出し（提供する値の並び）に直接書いた無名関数の中でだけ書けます。`impl` のメソッド・本体・別の場所の関数・見出しの無名関数の中の無名関数では型エラーです。別の場所から失敗を返すには、std の `try`（10 章）で `Fail` を `Result` にします。
- 提供した関数の中で使った要求は、その `with` より外側が提供します。
- `Async` は提供できません（`with Async(...)` はエラー）。`Async` を処理するのはランタイムと `spawn` だけです。提供する関数の中で `Async` を使えるのは、メソッドの宣言に `with Async` があるトレイト（`trait Config { fn load(self) -> Settings with Async }`）を提供する時だけです。そのメソッドの呼び出しは `Async<T>` の値になり、`.await` で待ちます（`with Config(fn() { fetch().await }) { load().await }`）。
- 本体が使わなかった要求は、型引数の無いトレイトなら提供できます。型引数のあるトレイト（`Need<T>`）は、本体が使わないと型引数が決まらないので型エラーです。

#### 非同期

`Async` は組み込みの要求で、待つ処理を表します。関数は `with Async` で宣言します。JavaScript の `Promise<T>` を返す外部関数は、`extern` に戻り値型 `T` と `with Async` を書きます（3.4 節）。

```
extern './js/util.ts' {
    fn later(x: number) -> number with Async
}

fn twice_later(x: number) -> number with Async {
    later(x).await + later(x).await    // 待つ場所に .await を書く
}

fn main() with Async {
    let a = twice_later(5)     // Async<number>。まだ走らない
    put(a.await)               // ここで走らせて待つ
}
```

- 宣言に `Async` を書いた関数（`extern` の `with Async`、メソッドの宣言に `with Async` があるトレイトのメソッドを含む）と、関数型に `Async` を書いた値の呼び出しは、型 `Async<T>` の値になります。この値は、呼び出しの時点では要求を使わず、本体も走りません。引数は呼び出しの時点で評価します。
- `e.await` は `Async<T>` の値 `e` を走らせて待ち、型は `T` です。この式が `Async` を要求します。`.await` は `Async<T>` の値にだけ付けられます。`f(x).await` は、この 2 つの規則の組み合わせです。
- 呼び出す関数が `Async` のほかの要求も持つなら、その要求は `.await` の時に使います（型は `Async<T with Fail<E>>` と表示します）。
- 同じ `Async<T>` の値を 2 回待つと、本体を 2 回走らせます。
- 要求の変数（`<R: Effect>`）を通した呼び出しには `.await` を書きません。`R` に `Async` が入るかは本体から分からないため、`R` に `Async` が入った呼び出しは、その場で待ちます（`map(xs, fn(x) { fetch(x).await })` の `map` の呼び出しも同じです）。書くと型エラーです。
- `T` の位置に `Async<T>` の値を使うと型エラーで、`.await` を付けるか `Async<T>` のまま受け取るよう伝えます。`Async<T>` の値を捨てる文（`fetch(x)` だけの文）と、戻り値が `unit` の関数の最後の式も型エラーです（警告の仕組みが無いため）。`put` と文字列化にも渡せません。

#### 色を止める

`Async` を要求する関数を呼ぶ関数も `Async` を持つ必要があります（関数の「色」が呼び出し元へ広がる）。これを止める方法は `spawn` だけです。`spawn(x)` は `Async<T>` の値 `x` を走らせ始め、`Task<T>` を返します。`spawn` 自体は要求を使わず、`Task<T>` は要求を持たない普通の値なので、`Async` を持たない関数から使えます。

```
fn on_click() {                              // Async を持たない
    spawn(save(doc)).then(fn(r) { show(r) })
}
```

| | `Async<T>` | `Task<T>` |
|---|---|---|
| 作り方 | `Async` を宣言した関数の呼び出し | `spawn(x)`（`x` は `Async<T>`） |
| 走り始める時 | `.await` か合流（`all`・`join`）で待つ時 | `spawn` の時 |
| 結果の受け取り方 | `.await`（`Async` を要求する） | `then(f)`・`peek()`。何もしなければ手放す |
| 要求 | 待つ所で `Async` と、関数の残りの要求 | 無い |

- `spawn` に渡す値は `Async` のほかの要求を持てません（型エラー）。失敗は本体の中で `try` などで `Result` にしてから渡します。
- `t.then(f)` は、処理が成功した時に `f(結果)` を呼びます。`f` は要求を持ちません。
- `t.peek()` は、成功していれば `Some(結果)`、未完了か失敗なら `None` を返します。
- `t.wait()` は型エラーです。非同期処理を待って値を使う場合は、開始前の `Async<T>` に `.await` を付けます。開始済みのタスクの成功後に処理する場合は `t.then(f)` を使います。
- JavaScript では、`spawn` が Promise を走らせ始め、状態（未完了・値・失敗）を持つオブジェクトを返します。`spawn` した処理の失敗は `console.error` に出し、`then` の関数は呼びません。
- インタプリタ・WASM・ネイティブは、JavaScript の Promise とマイクロタスク（Promise の続きを順に動かす仕事の並び）と同じ順で非同期処理を動かします。async 関数（`Async` を要求する関数、async にする無名関数、要求の多相な関数の async 版）はコルーチン（途中で止めて、後で続きから動かせる関数）にし、最初の `.await` まで動いて Promise を返します。`.await`・`all`・`spawn`・`then` は、JavaScript と同じ数の段を経て仕事の並びに続きを積みます。`main` が戻った後、仕事の並びが空になるまで動かします。
- `spawn` した処理で実行時エラー（`panic()`、整数の範囲外など）が起きた場合は、そのタスクを失敗にします。標準エラーに1回報告し、そのタスクに登録した `then` は呼ばず、別の仕事は続けます。
- `main` または `then` に渡した関数で実行時エラーが起きた場合は、残りの仕事を動かしてから、プログラム全体を失敗として終えます。`main` が失敗した場合はそのエラーを、成功した場合は `then` の関数で最初に起きたエラーを報告します。
- `then`・`peek` は std のメソッドで、組み込みの `task_then`・`task_done`・`task_value` を呼びます。`spawn` を使うファイルは std を読み込みます。

実装:

型検査の後に、提供を隠れた引数（文脈）で渡す形へ書き換えます（`src/check/context.rs`）。文脈は「要求のメソッドの名前 → 提供した関数」の組の並びで、内側の `with` が足した組から探します。

- 要求（トレイトか要求の変数）を持つトップレベルの関数と、すべての無名関数は、最後の引数に文脈を受け取ります。要求の無い関数の文脈は空です。
- 関数の値の呼び出しは常に文脈を渡します。文脈を受け取らないトップレベルの関数を値として使った時は、呼び出し側が渡した文脈を捨てます。
- 要求のメソッドの呼び出し `log(m)` は、文脈から提供した関数を引いて呼びます。
- `with T(値) { 本体 }` は、本体の前で提供を無名関数にして文脈に足します。提供した関数は `with` の外の文脈を写し取るので、その中の要求は外側が提供します。
- `all` は呼んだ所の文脈を受け取り、`Async<T>` の値を走らせる時に渡します。

| 実行方式 | 文脈 | exit | Async |
|---|---|---|---|
| インタプリタ | 組を構築子 `#ctx` の値でつなぐ | 抜け出す理由（`Flow::Abort`）として with まで戻す | 構文木を評価する Rust の `Future`（後から再開できる処理）を仕事の並びで動かす |
| JavaScript | 組をオブジェクト `{ k, f, up }` でつなぐ（`$cput`・`$cget`）。メソッドの宣言に `with Async` があれば、提供した関数を async にして待つ | 例外（`$Abort`）で with の `try` まで戻す | `Async` を持つ関数を `async function` にする。`Async<T>` は文脈だけを受け取って Promise を返す関数で、`.await` は `await v(文脈)` |
| WASM・ネイティブ（IR） | 組をランタイムの `__ctx_put`・`__ctx_get` で作り、引く | 中断の印（`__exit`）を置き、要求を持つ関数・関数の値の呼び出しの後で調べて 1 段ずつ戻す。with の本体は `Catch` で抜ける。async 関数の中断は Promise の失敗として待つ所まで運ぶ | async 関数はコルーチン（`src/backend/ir/coroutine.rs`）。Promise と仕事の並びは `runtime.hb` にあり、JavaScript と同じ順で動く |

型検査は、`.await` の直下の呼び出しをそのまま待つ呼び出しに、それ以外の `Async<T>` を作る呼び出しを「引数を一時変数に置き、その呼び出しを本体にした引数なしの無名関数」に、それ以外の `.await` をその値の呼び出しに書き換えます。出力側はこの書き換えの結果だけを扱います。

制限:

- 提供した関数は呼んだ所で 1 回だけ値を返せます。続きを複数回動かす（同じ要求の呼び出しから 2 回再開する）には、継続を実装する必要があります。
- 要求のメソッドそのものは値として使えません（`let f = log` は不可。`fn(m) { log(m) }` と包む）。
- `with` ブロックの本体と提供する関数の中では `return` を使えません。
- `Self` を引数や戻り値に使うメソッド（`fn eq(self, other: Self)`）は、要求として呼べません（対象の型が決まらないため）。
- `all` と `join` は最初の失敗で戻りますが、JavaScript では残りの処理は走り続けます（結果は捨てます）。取り消すには AbortSignal を各処理に通す必要があります。
- 型の評価で条件式が不透明な項（元の式を保持しない値）になった場合は、要求の節を明示します。

### 3.6 ライブラリの読み込み

`use` は、組み込みライブラリか hibana ファイルを読みます。`use util` は `util.hb`、`use foo::bar` は `foo/bar.hb` を、読み込み元のファイルと同じディレクトリから探します。読み込んだファイルの中の `use` も、そのファイルのディレクトリを基準に解決します。循環した依存と繰り返しの指定でも、同じファイルは1回だけ読みます。

### 3.7 トレイト

トレイトは、型ごとに実装を書けるメソッドの組です（例は `tests/programs/types/trait.hb`）。

```
trait Describe {
    fn describe(self) -> String
    fn shout(self) -> String { self.describe() + '!' }   // 既定の実装。impl で省ける
}

impl Describe for int {
    fn describe(self) -> String { 'int ' + self.to_string() }
}

impl<A: Describe> Describe for Vec<A> {           // 条件付きの実装
    fn describe(self) -> String { ... }
}

fn twice<A: Describe>(x: A) -> String { x.describe() + x.describe() }   // 制約。<A: Describe + Eq> で複数

trait Ord: Eq {                                   // 親のトレイト。Ord の実装には Eq の実装が要る
    fn lt(self, other: Self) -> bool
}
```

- `self` は実装する型の値です。トレイトの中の `Self` は実装する型で、`impl Describe for int` の中では `int` になります。`self` の型は省きます。
- メソッドは `x.describe()` で呼びます。`x.f()` は、`x` の型に属する関数 `T::f`（3.9 節）を先に探します。無ければ、`f` を持ち、`x` の型に適用できる実装があるトレイトを探します。候補のトレイトが複数あれば、呼び出し位置と各候補のメソッド宣言位置を報告して型エラーにします。
- `x.to_string()` は、`T::to_string` も `to_string` を持つトレイトの実装も無ければ、組み込みの文字列化になります。どの型の値にも使えます。
- 仕組みは辞書渡し（dictionary passing）です。トレイトは、メソッドの関数をフィールドに持つ構造体の型になり、`impl` はその型の値を作る関数になります。制約 `<A: Describe>` は、実装を受け取る隠れた引数です。呼び出す側では、型検査が型引数を求めた後に実装を探して、その引数を足します。探す順は、自分が制約で受け取った実装（その親のトレイトの実装を含む）、`impl` の順です。
- 実装は値なので、実行方式ごとの違いはありません。メソッドの呼び出しは、実装のフィールドを通した間接の呼び出しになります。
- `impl` を探すときは、型が一致し、制約の実装が見つかる候補を使います。適用できる候補が1件なら採用します。複数あれば、呼び出し位置と候補の宣言位置を報告して型エラーにします。宣言順で実装を選ぶことはありません。
- トレイトは `Self` のほかに型引数を持てます（`trait Convert<T> { fn convert(self) -> T }`）。実装は `impl Convert<String> for int`、制約は `<A: Convert<String>>` と書きます。内部では対象の型を先頭の型引数にした `Convert<int, String>` です。メソッドの型引数が呼び出しの引数から決まらない時は、実装から決めます。同じトレイトの実装候補が複数ある時は、期待する戻り値の型でも絞ります。
- 同じトレイトの制約のない実装どうしで、対象型とトレイトの型引数がすべて一致しうる場合は、宣言の重複として型エラーにします。具体型の一致と、制約のない型変数への当てはめを調べます。読み込んだモジュールをまたいで検査し、両方の宣言位置を報告します。トレイトの制約や型引数として渡す値の条件がある場合は、呼び出し時に実装を探す規則に従います。
- メソッドの戻り値の型に `never` を書けます。メソッドの宣言に要求（`with Async` など）を書けます。
- メソッドは自分のジェネリック引数を持てません。

`std` の `Display` は文字列化のトレイトです。実装がある型では `.to_string()`、埋め込み付きの文字列、`put` がその実装の `to_string` を使います。それ以外の場合は組み込みの文字列化を使います。

**等しさの比較**

- `==` は比較する型の `std` の `Eq`（等しさを定めるトレイト）の実装を使います。実装が見つからなければ、組み込みの比較を使います。`int`、`number`、`String`、`bool` などのプリミティブ型は組み込みで比較します。`!=` は `==` の結果を反転します。
- 組み込みの比較では、配列は長さと各要素、構造体と列挙型は構築子と各フィールドを比較します。比較が中に進むときも組み込みの規則を使います。`Ref<T>`（書き換えられる参照）と `Task<T>`（開始済みの非同期処理）では同一性を使います。参照は同じ書き換え先を指せば等しく、タスクは同じ処理を指せば等しくなります。参照先の値とタスクの結果は比較に使いません。
- 関数型と `Async<T>`（開始前の非同期処理）は比較できず、`Eq` 制約も満たせません。組み込みの比較が配列の要素や構造体・列挙型のフィールドをたどる場合にも適用します。関数をフィールドに持つ構造体に `Eq` を実装し、識別子などの比較で構造体の等しさを定めることはできます。
- 型引数の値を比較するには `<A: Eq>` のように制約を書きます。`Vec<A>` と `Option<A>` の標準ライブラリの実装は、要素型の `Eq` の実装を使います。型引数が未確定のまま、その型の値をフィールドに持つ独自の構造体を比較するには、その構造体に `Eq` を実装し、実装の中でフィールドを比較します。
- 組み込みの比較の型検査では、同じ型に戻ったらその枝の検査を終えます。型引数が変わり続ける再帰などで、構造体と列挙型をたどる深さが64段を超えると型エラーです。

```
use std -> *

fn same<A: Eq>(a: A, b: A) -> bool { a == b }
fn id(n: int) -> int { n }
fn step() -> int with Async { 42 }

fn main() {
    put(same(1, 1)) // true
    // put(id == id) // 型エラー。関数型の比較
    // put([step()] != [step()]) // 型エラー。配列の要素が Async<int>
    // put(same(id, id)) // 型エラー。関数型は Eq 制約を満たせない
}
```

トレイトは `with` の要求にも使えます（`with Logger(logger)`、`with Fail<E>`）。要求と提供の規則は 3.5 節です。

### 3.8 テスト

```
use std -> *

test '足し算' {
    assert_eq(add(1, 2), 3)
    assert(add(0, 0) == 0)
}

test '引き算' {
    let base = 10
    describe '正の数' {
        it '1 を引く' { assert_eq(base - 1, 9) }
        it '10 を引く' { assert_eq(base - 10, 0) }
    }
}
```

- `test '名前' { 本体 }` は、引数の無い関数として型検査します。`hibana test` でだけ実行し、ほかの実行方式では呼びません。`test` は宣言の先頭で文字列が続く時だけ特別で、変数名にも使えます。
- 本体で実行時エラーが起きると、そのテストは失敗です。std の `assert(ok)` と `assert_eq(got, want)`（`Eq` と `Display` の実装が要る）は、組み込みの `panic` で実行時エラーにします。失敗の位置は、ライブラリの中で起きたエラーでも、テストのファイルの中の呼び出しにします。
- `main` の無いファイルには、空の `main` を足して検査します。
- 本体の中の `describe '名前' { ... }` はテストをまとめ、`it '名前' { ... }` は1件のテストになります。`it` があると、`it` ごとに1件として実行し、名前は `test` から順に ` / ` でつなぎます（`引き算 / 正の数 / 1 を引く`）。`it` より前に書いた文（外側の `test` と `describe` の中のもの）は、その `it` の本体の前に毎回実行します。`it` の無い `describe`、最後の `it` と `describe` の後の文はエラーです。`describe` と `it` は、後に文字列と `{` が続く時だけ特別で、変数名にも使えます。

### 3.9 型に属する関数とメソッド

```
struct Param { value: String }

fn Param::get(p: Param) -> String { p.value }     // 型 Param に属する関数
fn String::twice(s: String) -> String { s + s }         // 組み込みの型にも書ける

fn main() {
    let id = Param { value: 'u7' }
    put(Param::get(id))       // u7
    put(id.get().twice())     // u7u7。x.f(a) は、x の型 T の T::f(x, a) を呼ぶ
}
```

- `型の名前::名前` は1つの名前です。関数の宣言・呼び出し・`use ... -> { 名前 }` のどこでも書けます。
- `x.f(a)` は、`x` の型を求めてから `T::f(x, a)` の呼び出しに書き換えます。`T::f` が無ければエラーです。`String`・`int`・`Vec` などの組み込みの型のメソッドは、どのモジュールで宣言しても使えます。
- `T::f` と `T__f` は異なる名前です。修飾名は型と関数の名前を分けて保持します。
- ponytail: 同じ組み込みの型に同じ名前のメソッドを複数のモジュールが宣言すると、名前の順で最初のものを使います。

## 4. 式

| 式 | 例 |
|---|---|
| リテラル | `1` `'s'` `` `n={n}` `` `true` `[1, 2, 3]` |
| 変数 | `let x = 1`、`let mut i: int = 0`、`i = i + 1` |
| 演算 | `+ - * / % **`（`+` は文字列の連結にも使う。`**` はべき乗）、`< <= > >= == !=`、`&& \|\| !` |
| 呼び出し | `f(x)`、`f<int>(x)`、`adder(10)(5)` |
| 条件 | `if c { a } else { b }`（`else` が無ければ値は捨てる。片方の分岐だけで型が決まらない `None` や `[]` は、もう片方の型になる） |
| 繰り返し | `while c { }`、`for x in v { }`（`v` は `Vec`）、`for i in a..b { }` |
| 繰り返しの制御 | `break` で囲んでいるループのうち最も内側の本体を抜ける。`continue` で本体の残りを飛ばし、`while` の条件を調べ直すか `for` の次の要素に進む |
| 場合分け | `match o { None -> 0, Some(x) -> x }`（腕は改行か `,` で区切る。`_` は残りすべて）。パターンは入れ子にできる（`Some(JInt(n))`、`Shape::Circle(Point { x, y: 0 }, r)`、`UserId(id)`）。文字列・数・`true`・`false` のリテラルも照合できる（`match s { 'red' -> 1, _ -> 0 }`） |
| 分解 | `let Point { x, y } = p`、`let Point { x: a, y: _ } = p`、`let UserId(id) = u`。構造体（入れ子の構造体を含む）だけを分解でき、フィールドごとの `let` になる |
| 無名関数 | `fn(x: int) -> int { x + 1 }`、期待する型があれば `fn(x) { x + 1 }` |
| 配列 | `v[i]`、`len(v)` |
| 構造体 | `Point { x: 1, y: 2 }`、`p.x` |
| ブロック | `{ let a = 1; a + 1 }`（最後の式が値） |

- `match` は網羅していなければエラーです。入れ子のパターンでは、足りない場合を元のパターンの形（`Some(JNull)` など）で示します。リテラルのパターンには、残りを受ける `_` か束縛の腕が要ります（`true` と `false` を両方書いた場合を除く）。同じ位置に構築子とリテラルのパターンは混ぜられません。
- パターンの中の名前は、フィールドの無い構築子（`None`）なら構築子、それ以外は束縛です。腕の先頭に書いた名前だけのパターンは構築子です。入れ子のパターンは構文解析で平らな `match`・`if`・`let` に書き換え、束縛にもフィールドの型（細分化型の条件を含む）が付きます。
- `break` と `continue` はループの本体で使えます。無名関数（`with` で提供する関数を含む）や `quote` の `${ }` から、その外のループへは移れません。
- 範囲の `for` は、両端を最初に一度ずつ評価します。
- `**` は単項の `-` `!` より強く結合し、右から結合します（`-x ** 2` は `-(x ** 2)`、`2 ** 3 ** 2` は `2 ** (3 ** 2)`）。整数演算では負の指数と範囲外の結果が実行時エラーです。`number` の演算では整数値であれば負の指数も指定できます。
- 無名関数は作った時の変数の値を写し取り、呼び出しのたびにその値から始めます。写し取った `let mut` 変数への代入は、その呼び出しの中で有効です。呼び出し間で書き換えた値を共有するには `Ref`（書き換えられる参照）を使います。

## 5. 型

| 型 | 意味 |
|---|---|
| `int` `number` `bool` `String` `unit` | 53ビット安全整数・有限な64ビット浮動小数点数・真偽値・文字列・値の無いこと |
| `Vec<T>` | 配列。書き換えられないので、`Vec<int[x -> x > 0]>` は `Vec<int>` として使える。逆向きには使えない。入れ子の `Vec` でもこの向きで判定する |
| `Ref<T>` | 書き換えられる参照。`new_ref(x)` で作り、`read(r)` で読み、`write(r, x)` で書く。無名関数や with で提供する関数が写し取っても同じ値を指す（`mut` 変数は写し取った時の値になる） |
| `Async<T>` | まだ走っていない非同期の処理。`.await` で待つと `T` になる（3.5 節） |
| `Task<T>` | `spawn` で走らせ始めた処理。要求を持たない値で、`then`・`peek` で結果を受け取る（3.5 節） |
| `(x: A, B) -> C` | 関数型。引数名は省ける。細分化型の条件では前の引数の値を参照できる |
| `T[x -> 条件]` | 細分化型。条件を満たす `T` の値だけを許す |
| `Type` | 型引数に指定する種類。`<A: Type>` は `<A>` と同じ |
| `syn`、`syn<種類>` | コード片。マクロ本体の中でだけ使う（8 節） |

## 7. 検査

### 7.1 細分化型の証明

細分化型の条件、配列の添字の範囲（`0 <= i && i < len(v)`）、`/` と `%` の割る数が 0 でないこと（`d != 0`。示せなければ `0 < d || d < 0` も試す）は、コンパイル時に証明します。割る数は `int[d -> d != 0]` などの細分化型か、`if d != 0 { ... }` の条件で示します。割る数を `int` から `number` に変換して演算する場合も、整数として得た条件を使えます。

1. 値が分かれば計算して確かめます。
2. 分からなければ、その位置で成り立つ事実と照合します。事実は、細分化型を持つ変数・引数・構造体のフィールドの条件、`if` / `while` の条件（`else` 側では否定）、`for i in a..b` の `a <= i < b`、`a && b` の `b` での `a`（`||` では否定）、`break` で抜ける箇所がない `while` の後での条件の否定から集めます。
3. 照合では、字面の一致と `a <= b + k` の形の弱め（例: `0 <= i` から `0 <= i + 1`、`2 <= n` から `0 <= n - 1`）を試します。両辺の定数は `k` に寄せて比べます。次に、`x == 定数` の事実で目標の `x` を置き換えて計算します（例: `len(parts) == 2` から `0 < len(parts)`）。
4. それでも示せなければ Z3 に問い合わせます。`HIBANA_NO_Z3` を設定すると Z3 を使いません。例のうち Z3 が要るのは、`smt.hb` と掛け算の条件を持つ `struct.hb` だけです（比較・`&&` `||` `!`・`+ - *` を Z3 の項に訳し、訳せない項は記号にします）。

代入された変数についての事実は捨てます（型の条件は残します）。`while` / `for` の中で代入される変数についての、ループに入る前の事実も捨てます。範囲の両端についての事実も、ループ中に代入される変数に依存するものは捨てます。

呼び出しの記号計算は、`len`、型コンストラクタ（型引数から型を作るもの）、データ構築子、純粋な組み込み演算、`type` 別名に限ります。それ以外の実行時関数は、名前と引数が同じでも呼び出すたびに別の値として扱います。`read`・`input`・`now_ms`・効果を持つ関数もこれに含みます。読み取った値を変数に束縛した場合は、その変数についての事実を使えます。

## 8. マクロ

### 8.1 構文の宣言

```
syntax Route = annotations:Annotation* method:Ident path:String body:Block
macro routes ('routes' '{' rs:Route* '}') -> Expr { ...本体... }
```

パターンの書き方:

| 書き方 | 意味 |
|---|---|
| `'lit'` | リテラル（1個のトークンでなければならない。`'Response::json'` は1つの名前として照合する） |
| `Ident Int Float String Template Expr Block Stmt Type Text` | 組み込みの項。`Template` は `` `...` `` の文字列で、`str_of` はソースのままの中身（`{ }` を含む）を返す。`Text` は、後に続きうるトークンの手前までの生の文字列 |
| `Name` `module.Name` `module::Name` | 他の `syntax` 規則 |
| `x:P` | 束縛。同じ連接の中で同じ名前を2回使うとエラー |
| `P*` `P+` `P?` `P % sep` | 0回以上・1回以上・省略可能・区切り付きの並び |
| `~P` | 直前のトークンと空白なしで続く |
| `A \| B` | 順序付きの選択（先に一致した方を採る） |
| `( P )` | グループ |

- `Text` には `Don't` のように語に続く一重引用符を書けます。通常の字句解析と構文解析が成功する場合は、その解釈を使います。
- パターンに修飾なしで書いた規則名は、宣言元のモジュール、`use m -> *` や `use m -> {Name}` で取り込んだ規則の順に探します。取り込んだ複数の規則が同じ名前なら参照時にエラーになります。`use m` を書くと、`m.Name` または `m::Name` で参照できます。
- マクロの照合対象は、自分のモジュールと、そのファイルから直接 `use` したモジュールのマクロです。`use m` と `use m -> *` はすべてのマクロを照合対象にします。`use m -> {show}` は宣言名が `show` のマクロだけを照合対象にします。呼び出しはパターンに従います。
- マクロは、式の位置（`-> Expr`、省略時）か文の位置（`-> Stmt`）で、組み込みの構文より先に試します。一致しなければ組み込みの構文として読みます。複数のマクロが一致すると「Ambiguous macro match」エラーになり、候補がモジュール名付きで表示されます。
- `-> Decl` は宣言の位置で展開します。展開した型・関数・実装を含めて名前を集め直し、型検査します。展開の入れ子は64段未満です。
- 左再帰（`syntax E = E '+' Int`）と、`Expr` / `Stmt` で始まるマクロは禁止です。
- `syntax` 宣言の末尾の `;` は省けます。

### 8.2 本体

マクロ本体はコンパイル時に実行する普通の hibana のコードで、最後の値（`syn` 型）が展開結果になります。本体が空なら照合結果だけを残し、型検査で「展開コードが無い」エラーになります。

```
macro pow ('pow' '(' x:Expr ',' n:Int ')') {
    let mut acc = quote { 1 }
    let mut i = 0
    while i < int_of(n) {
        acc = quote { $acc * $x }
        i = i + 1
    }
    acc
}
```

- `quote { ... }` はコード片を作ります。中では `$x`（変数の値）、`$x.f`（フィールド）、`${式}`（式の値）、`$( ... ) 区切り? *`（配列を繰り返す）が使えます。差し込める値は `syn`・`int`・`String`・`bool` です。
- パターンで束縛した式は、括弧で囲んで差し込みます（`-sum(1 + 2)` は `-(1 + 2)`）。`quote` で作った断片は囲みません。
- 束縛の型は、パターンから決まる `syn<種類>` です（`p:Pair` は `syn<Pair>`、`ps:(Pair % ',')` は `syn<[Pair]>`、`x:Expr` は `syn<Expr>`）。存在しないフィールドの参照や、配列でない値への `at` は、マクロ定義の時点で型エラーになります。
- 組み込み関数: `len(x)`、`at(xs, i)`、`is_null(x)`、`int_of(x)`、`str_of(x)`、`ident(s)`（文字列から識別子を作る）、`error(msg)`（コンパイルエラーにする）。文字列の関数（9 節）も使えます。マクロ本体の `put` は標準エラーに出ます。
- `str_of` は規則の照合結果と型の構文片にも使えます。この場合は元のトークンの綴りを返します。
- 式マクロが複数の文を生成した場合はブロックにまとめ、最後の式を値にします。`quote` 内の文字列リテラルの `${式}` は、式の値を文字列にして埋め込みます。`'${ann.ident}'` のように文字列の全体にも、`'[${ann.ident}] ${x}'` のように途中や複数の場所にも書けます。構文片（syn）は `str_of` と同じく綴りを、`String`・`int`・`bool` は文字列にした値を埋め込みます。対応する `}` が無い `${` はエラーです。文字列の中に `${` を文字どおり書く方法はありません。
- 本体から普通の `fn` は呼べません。マクロは関数の構文解析より前に実行するためです。

本体で、パターンで束縛した名前に `.do()` を付けて書くと（`expr.do()`）、そのマクロは雛形になります。雛形の本体はコンパイル時に実行せず、呼び出し位置で実行するコードとして展開します。`x.do()` は束縛した式やブロックをその位置で実行し、本体の `return` はマクロの値を返します。例は `tests/programs/macros/template.hb` です。

```
macro unless('unless' expr:Expr block:Block) {
    if ! expr.do() {
        return block.do()
    }
}
```

- 雛形の本体は `quote { { 本体 } }` と同じに扱い、`x.do()` は `$x` になります。名前の付け替え（8.3 節）も同じです。本体の中の名前は呼び出し側の変数と衝突せず、差し込んだブロックの中の `return` や代入は、呼び出し側の関数と変数に効きます。
- 本体の `return` は、その後の文を `return` しなかった分岐に移して、式の値にします。`return` を書けるのは、本体の文と、`if`・ブロックの中です。`while`・`for`・無名関数・`let` の右辺の中に書くとエラーです。どこでも `return` しなければ、本体の最後の式が値です。
- 雛形の本体ではコンパイル時の計算（`quote` や `len(rs)` など）はできません。

### 8.3 衛生性

`quote` に直接書いた識別子は、展開ごとに固有の名前（`tmp#3`）に付け替えます。展開したコードの変数が、呼び出し側の変数と衝突しません。関数名・型名・構築子名・組み込み関数・パターンのリテラル・`.` の後のフィールド名・`Name { x: 式 }` の `x`（構造体のフィールド名）は付け替えません。ただし、同じ `quote` の中で `let`・`for` の変数、`fn` の引数、`match` の腕と無名関数の引数の束縛になる名前は、関数名や組み込みの関数と同じでも付け替えます（`let len = 1` の `len` など）。その名前を同じ `quote` の中で大域の関数として呼ぶと、その呼び出しも付け替えられるので、避けてください。`$x` で差し込んだ呼び出し側のトークンと、`ident(s)` で作った識別子も付け替えないので、呼び出し側から見える名前を導入できます。

展開したコードの中にマクロの呼び出しがある場合、パターンに一致する先頭のトークンの出所で照合対象を決めます。`quote` に直接書いた呼び出しは定義側、`$x` で差し込んだ呼び出しはその箇所を書いたファイルの `use` に従います。

名前の公開範囲も出所で判定します。`quote` に直接書いた名前は、マクロを定義したモジュールの権限で検査するので、別のモジュールから呼ばれたマクロも定義側の非公開の関数・型・フィールドを使えます。`$x` で差し込んだ式は呼び出し側の権限のままで、定義側の非公開の名前を書けばエラーです。宣言マクロ（`-> Decl`）の展開結果は呼び出したモジュールの宣言なので、呼び出し側の権限で検査します。

## 9. 組み込み関数

| 関数 | 型 |
|---|---|
| `put(x)` | 任意の値を表示する |
| `input()` | 標準入力から1行読み、`String` を返す。WebAssembly ではホストの読み取り関数を使う |
| `refine<T>(value)` | `Result<T, String>`。`int`・`number`・`String`・`bool` の細分化型 `T` の条件を実行時に検査する。`refine<int>` とその細分化型には `number` も渡せ、整数性と安全整数の範囲を検査してから追加条件を検査する。`value` は一度だけ評価し、条件を満たせば `Ok`、満たさなければ `Err` を返す。検査は通常の分岐に展開し、成功する枝で条件を証明する。条件には見えている変数（引数・`let`・`for` の変数）を使え、`value` を評価する前にその値を写して検査する。データ型の細分化条件は未対応 |
| `len(v)` | `Vec<T>` か `String` の長さ。`mut` の変数は、初期値と `push`・`set_at` の代入から長さを追う（ループと分岐の後は分からなくなる） |
| `x.to_string()` | 任意の値を文字列にする（3.7 節） |
| `split(s, sep)` | `(String, String) -> Vec<String>` |
| `starts_with(s, p)` | `(String, String) -> bool` |
| `slice(s, i, j)` | `(String, int, int) -> String`。範囲外は実行時エラー |
| `chars(s)` `code(c)` | `String -> Vec<String>`（1 文字ずつ）、`String -> int`（先頭の文字の番号。空なら -1） |
| `panic(msg)` | `String -> never`。実行時エラーにする |
| `now_ms()` | `() -> int`。1970 年 1 月 1 日（UTC）からのミリ秒 |
| `new_ref(x)` `read(r)` `write(r, x)` | `T -> Ref<T>`、`Ref<T> -> T`、`(Ref<T>, T) -> unit` |
| `push(v, x)` | `(Vec<T>, T) -> Vec<T>`。`v` の後ろに `x` を足した新しい `Vec`（`v` は変わらない）。`xs = push(xs, x)` の形で、`xs` の配列を他から指していなければ、写さずにその場で足す（平均 O(1)） |
| `set_at(v, i, x)` | `(Vec<T>, int, T) -> Vec<T>`。`v` の `i` 番目を `x` にした新しい `Vec`。`i` が範囲内であることを添字と同じく証明する。`xs = set_at(xs, i, x)` の形は `push` と同じく、その場で書き換える（O(1)） |
| `all(xs)` | `(Vec<Async<T>>) -> Async<Vec<T>>`。`.await` で待つ（3.5 節） |
| `spawn(x)` | `(Async<T>) -> Task<T>`。要求を使わない。`x` は `Async` のほかの要求を持てない（3.5 節） |
| `task_then(t, f)` `task_done(t)` `task_value(t)` | std の `Task::then`・`Task::peek` の実装用の組み込み関数 |

`std::math`・`std::build`・`std::fs` の関数（10 章）は、利用者のコードからは呼べない組み込み関数で実装しています。これらの組み込み関数は、組み込みのライブラリの外からは未定義の関数として扱います。利用者のファイルの名前が `math.hb` などでも同じです。

`input()` は行末の改行（LF）と、その直前にある復帰（CR）を除きます。改行のない最終行は末尾の復帰も含めて返します。空行や、入力が終わって読み取るバイトがないときは空文字列を返します。行は UTF-8（文字の符号化方式）として読み、先頭の U+FEFF も文字列に含めます。

標準入力の読み取りに失敗したときは「標準入力を読めません」、UTF-8 として解釈できない行を読んだときは「標準入力の文字コードが UTF-8 でない」の実行時エラーになります。コマンドとして実行した `main` がこのエラーで失敗すると、失敗前の出力を保持し、標準エラーに1回報告して終了コード1を返します。WebAssembly の公開関数を JavaScript の接続コードから呼ぶ場合は、エラーを例外として返します（11.1 節）。

組み込みの表示では、`Task<T>` は完了状態にかかわらず `<task>` と表示します。モジュールで宣言した構築子と型は、書き方と同じくモジュール名を `::` で付けて表示します（`std::Ok(3)`、`std::Some(std::Pair { first: 1, second: 2 })`）。利用者のファイルで宣言したものにはモジュール名を付けません。エラーメッセージの名前も同じ形です。`put` に直接渡した文字列はそのまま表示します。配列の要素や構造体のフィールドなど、他の値の中にある文字列は二重引用符で囲みます。内部の二重引用符とバックスラッシュは `\"` と `\\`、後退・タブ・改行・改ページ・復帰は `\b`・`\t`・`\n`・`\f`・`\r` で表します。残りの制御文字（U+0000〜U+001F、U+007F〜U+009F のうち、前述の表記を使わない文字）は `\u0000` のように `\u` と小文字の16進数字4桁で表します。

`number`（64 ビット浮動小数点数）の組み込みの文字列化では、元の値に丸め戻せる最少の有効桁数で十進表記を作ります。その桁数で元の値に最も近い候補を選び、等距離なら有効桁の末尾が偶数の候補を選びます。指数表記は使いません。正のゼロは `0`、負のゼロは `-0` と表示します。この規則は `put`、`to_string()`、配列や構造体に含まれる `number` の表示に適用します。

## 10. ライブラリ

### std::math

`use std::math` で読み込み、`math::sqrt(9)` で呼びます。`use std::math -> { floor }` で名前を取り込むと `floor(-2.5)` と呼べます。`sqrt(x)` は平方根を `number[r -> r >= 0.0]` で返し、負の引数は実行時エラーです。`floor(x)` は小数部分を負の無限大に向かって切り下げた `int` を返し、結果が `int` の範囲外なら実行時エラーです。

### std::build と std::fs

ビルドスクリプト（11.1 節）用の関数です。`use std::build`・`use std::fs` で読み込みます。インタプリタでの実行（`hibana <ファイル>`）でだけ使え、JavaScript・WASM・ネイティブの出力から辿れるとコンパイルエラーです。経路は、実行したファイルのディレクトリから数えます。コンパイルするファイルの中の `use` は、そのファイルのディレクトリから探します。

| `build::write_executable(path, bytes)` | `(String, Vec<int>) -> unit`。実行権限を付けてファイルに書く。親ディレクトリが無ければ作る。実行権限は Unix でだけ付ける |

- `empty()` の型引数は引数から決まらないので、`let e: Map<int> = empty()` のように期待する型を書きます。

- JSON の文字列は `\uXXXX` と、サロゲートペア（2個の Unicode エスケープで1文字を表す形）を読みます。

## 11. 実行方式

目標は Web とネイティブの両方です。型検査を通ったプログラムから型を消し、出力先ごとのバックエンドでコードを作ります。型と証明は実行に影響しないので、どのバックエンドも普通の値と関数だけを扱います。

### 11.1 コマンドとコード生成 API

ファイルを指定した実行は `hibana <ファイル>` で行います。JavaScript・WASM・ネイティブの生成物は、インタプリタで実行するビルドスクリプトから `std::build` と `std::fs`（10 章）で書き出せます。Rust API からも利用できます。

| コマンド | 出力 | 用途 |
|---|---|---|
| `hibana <ファイル>` | 構文木を直接評価して実行 | 開発中の確認。マクロもこの評価器で行う |
| `hibana fmt <ファイル>` | ファイルを整形して書き戻す | 整形。トークンの並びと改行の位置は変えず、字下げ（空白4つ）・行内の空白（`,` の後、`=` `==` `&&` `->` などの前後、`{ }` の内側。`->` の前に揃えるための空白が2つ以上あれば残す）・空行（続く空行は1行、括弧の直後と閉じ括弧の前は無し）・コメントの位置を整える。設定は無い。マクロで定義した JSX 形式の要素（`<tag ...>` から `</tag>` まで）と `$( )` `${ }` の中は元のまま（`Text` 規則では空白も文字列になるため）。`+ - * /` の前後は元の空白のまま。行の長さで改行の位置は変えない |
| `hibana test <ファイル...>` | `test` をインタプリタで実行し、成功した数を表示する。失敗があれば終了コード 1。ファイルを引数で指定する | テスト（3.8 節） |

ビルドスクリプトは普通の hibana のプログラムです。生成する形式と書き出す場所はスクリプトに書きます。`std::build` と `std::fs` の関数を JavaScript・WASM・ネイティブの出力から辿れるとコンパイルエラーです。

```
use std::build
use std::fs

fn main() {
    fs::write_bytes('dist/app.mjs', build::compile('src/app.hb', 'js'))
    fs::write_bytes('dist/app.wasm', build::compile('src/app.hb', 'wasm'))
    build::write_executable('dist/app', build::compile('src/app.hb', 'native'))
}
```

`hibana build.hb` で実行します。経路はスクリプトのディレクトリから数えるので、どのディレクトリから実行しても同じ場所に書き出します。`build::compile` の `wasm` は `main` を持つ実行用の WASM（`to_wasm` と同じ）です。`build::compile_wasm` に公開関数名を渡すと WASM ライブラリと受け渡し規約を取得できます。正本の例は `examples/build.hb` です。`std::wasm_web` はその規約から JavaScript の接続コードと TypeScript の型宣言を生成します。[WebAssembly の生成例](wasm.md)

WASM 出力は関数を名前で公開します。`int` と `number` は `f64` と JavaScript の `Number` で渡します。`int` は安全整数の範囲と整数性、`number` は有限性を入口で検査します。`int` の負の0は正の0へ正規化します。`put` は取り込み `hibana.write(fd, 位置, 長さ)`、`input` は `hibana.read(fd, 位置, 長さ) -> 読み取ったバイト数`、`now_ms` は `hibana.now_ms()` を呼びます。JavaScript の接続コードは、出力を `imports.hibana.print`（無ければ `console.log`）に渡します。読み取りは `imports.hibana.read(fd, Uint8Array) -> バイト数` を使い、指定が無ければ Node.js の標準入力を読みます。入力終了は0、失敗は負の値です。実行時エラーでは、メッセージの文字列の位置を memory の24番地に書いて WASM の実行を停止します。JavaScript の接続コードは、メモリを参照できる場合、その文字列を例外のメッセージとして呼び出し元に返します。

ライブラリは `hibana::to_wasm_library(source, &exports)` に公開する関数名を渡して生成します。`main` は必要ありません。型検査はライブラリ全体に行い、WASM には公開関数と、そこから呼ぶ関数だけを含めます。未使用の関数や型が IR に未対応でも、型検査を通れば含めません。

WASM の公開関数の引数と、外部関数の戻り値に細分化型を指定するとコンパイルエラーになります。配列の要素と構造体のフィールドにも同じ規則が適用されます。公開関数を自動で選ぶ場合、細分化型を受け取る関数は内部関数として扱います。

WASM の公開関数は標準ライブラリの `Result<T, E>` を戻り値にできます。`T` と `E` は境界から返せる型です。`std::wasm_web` が生成する接続コードは `Ok(value)` を `{ ok: true, value }`、`Err(error)` を `{ ok: false, error }` に変換します。

`with Async` の公開関数は、仕事の並びが空になるまで WASM 内で処理を進め、完了した値を境界の型に変換して同期で返します。

`std::wasm_web` の接続コードは `instantiate` に WASM のバイト列と必要な外部関数を受け取ります。公開関数・外部関数の整数は JavaScript の `number` で受け渡し、接続コードと WASM の入口で安全整数を検査します。文字列の受け渡しと入出力用の内部呼び出しには64ビット整数を使います。型情報の形式と接続コードの生成例は [WebAssembly](wasm.md) を参照してください。

JavaScript、IR、実行用 WASM、ネイティブの実行ファイルは、それぞれ `hibana::to_js`、`hibana::to_ir`、`hibana::to_wasm`、`hibana::to_native` で生成します。API は文字列やバイト列を返し、ファイルへの保存は呼び出し側で行います。`to_wasm` と `to_native` は `main` から辿れる関数だけを含めます。

Rust の `hibana::compile_wasm_library(source, &exports)` も、同じ型検査結果から WASM のバイト列と受け渡し規約を返します。`hibana::pipeline` の `load` は `use` のファイルを読み、`parse` はファイルごとに構文解析します。`check` は型検査し、`lower` は IR を作り、`link` は IR から公開関数とその呼び出し先を選びます。`emit_wasm` は WASM のバイト列、`wasm_abi` は受け渡し規約の JSON を返します。

IR は WASM とネイティブの共通の中間表現です。制御フローは WASM と同じ入れ子の形（`if`・`while`・`break`・`continue`・`return`）で持ちます。値は型の番号と中身の2つの64ビット整数で表し、`number` の中身には浮動小数点数のビット列を置きます。文字列の連結・比較・表示や組み込み関数は、hibana の構文で書いたランタイム（`src/backend/runtime.hb`）にあり、同じ変換で IR にします。ランタイムは型検査を通さず、`__load` などの組み込みを IR の命令に直接変換します。`with` ブロックは、`exit` と抜けた腕の中断の印を呼び出しの後で調べ、1段ずつ戻って抜けます。`lower(&checked, Some(&exports))` に公開関数を渡すと、使う関数だけを変換できます。WASM の境界は `int`・`number`・`String`・`bool`・`unit` と、それらの `Vec` と型引数の無い構造体に対応します（`docs/wasm.md`）。WASM モジュール同士のリンクは未対応です。

ネイティブの出力（`hibana::to_native`）は、IR を Cranelift（Rust で書かれたコード生成器）で機械語にし、libc を使わない静的な ELF の実行ファイルを返します。機械語と文字列定数は RX（読み取り・実行）、可変状態 `__static` は RW（読み取り・書き込み）の PT_LOAD（読み込むメモリ区画）に分け、4096バイトのページ境界で区切ります。リンカーは使わず、入力・出力・終了・メモリの確保（mmap）・時刻は Linux の syscall を直接呼びます。現在は x86-64 の Linux に対応します。外部関数には対応しません。実行時エラーでは、標準エラーにメッセージを書いて終了コード1で終わります。

`hibana::to_wasm` は `main` を持つ実行用 WASM を返します。実行するには WebAssembly の実行環境が必要です。

どのバックエンドも、インタプリタと同じ出力になることをテスト（`tests/programs/` と `examples/` のすべてのプログラム）で確かめています。`fib(30)`（約135万回の関数呼び出し）は、ネイティブ 0.007 秒、Node.js 0.11 秒、インタプリタ 1.8 秒でした。

## 12. 既知の制約

- `int` の範囲は全実行方式で ±(2^53 − 1) です。JavaScript と WASM の数値境界で `BigInt` は使いません。
- IR を通す WASM とネイティブの出力は、マーク＆スイープの GC で確保したメモリを回収します。区画を分けたりつないだりしないので、1024 バイトより大きい区画は 2 のべきに切り上げて確保します（最大で 2 倍の無駄）。関数の局所変数の写し（シャドースタック）は WASM で 4 MB、ネイティブで 16 MB で、超える深さの再帰は実行時エラーです。
- 実行時エラーの位置は、インタプリタではエラーを起こした一番内側の式、JavaScript では最後に通った失敗しうる式（算術・`slice`・要求の呼び出し・JavaScript の関数の呼び出し）です。JavaScript の関数の中で投げられた例外は、その呼び出しの位置になります。
- エラーの下線には、メッセージの一番内側の部分を説明に付けます。未定義の名前には綴りの近い名前（編集距離 2 以下）を、文字列が必要な所の数値には `.to_string()` を提案します。関数を呼んで提供の無い要求を使った時は、その関数の中で要求のメソッドを呼んでいる位置にも下線を引きます（その関数が直接呼ぶものだけを探します）。
- Z3 には `int` を上限の無い整数として渡します。オーバーフローは実行時に検査しています。`/` と `%` は Z3 に訳しません。
- 細分化型の条件内で束縛する変数は、名前によらず同じ内部表現に置き換えてから条件を評価します。`int[x -> x > 0]` と `int[y -> y > 0]` は同じ型です。論理的に同値でも、評価後の形が異なる条件は、型の同一性の判定では一致しません。値が条件を満たすかは 7.1 節の手順で証明します。
- 実行時には型引数が消えているので、型引数を値として表示すると `?` になります。
- マクロの `Text` はトークン単位で切り出します。本文中の文字列リテラルに照合の区切りが含まれるときは、その文字列の途中では `Text` を止めません。
- マクロ照合の途中で起きたコア構文のエラーは「照合失敗」として巻き戻すので、入れ子のマクロの曖昧性エラーは表に出ません。

これらの多くは、コード中に `ponytail:` の注釈で、上限と改善の方向を書いてあります。
